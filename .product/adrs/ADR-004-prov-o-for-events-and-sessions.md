## Context

The orchestration substrate needs an auditable, machine-readable lineage model for events and sessions:

- Which mutation caused which event?
- Which session produced which artifact?
- Which bundle / model / value-stream did a session use?
- How did `CodeChange:X` come into existence?

Several options exist: custom triples, opaque audit logs, ad-hoc `caused_by` properties. The standards-track answer is **W3C PROV-O** — the Provenance Ontology — which provides `prov:Entity`, `prov:Activity`, `prov:Agent`, `prov:wasGeneratedBy`, `prov:wasDerivedFrom`, `prov:used`, `prov:wasAttributedTo`, and a documented vocabulary for exactly this lineage problem.

See `decision-cli-slice-1-bounds.md` §5.2 (Event with PROV-O provenance), §5.3 (Session records with PROV-O lineage), §11.1, §11.2 (invariants requiring PROV-O reachability).

## Decision

Adopt **PROV-O** as the lineage vocabulary for events and sessions in decision-cli's graph.

Concrete usage:

- **Events** are `prov:Entity` instances generated by the mutation that produced them: `Event prov:wasGeneratedBy Mutation`.
- **Sessions** are `prov:Activity` instances. The bundle, model version, and ValueStream they used appear as `prov:used` references. Outputs (e.g., `CodeChange`) are linked by `prov:wasGeneratedBy Session`.
- **Bootstrap session** (`dec:session/init-001`) records PROV-O links to the definition source, its content hash, the validation result, and the ontology version.
- **Cross-stream artifacts** (later slices) carry PROV-O links to their source stream.

PROV-O coexists with `dec:`-namespaced vocabulary; nothing here precludes adding application-specific properties.

## Consequences

**Positive:**

- Lineage queries become standard SPARQL against a published vocabulary.
- Tooling that understands PROV-O (visualisers, validators, exporters) works out of the box.
- The `dec session log <id>` command (FT-012) is a SPARQL walk over `prov:` properties.

**Negative / accepted costs:**

- PROV-O is verbose: a single session may produce a dozen triples just for lineage.
- Slight learning curve for contributors unfamiliar with the vocabulary.

**Invariants this ADR justifies:**

- Every `Session` record links to its bundle hash, model version, and ValueStream via PROV-O.
- Every `CodeChange` has a corresponding `Session` reachable via PROV-O.
- The bootstrap session record is reachable via PROV-O from the ValueStream artifact.

## Status

Accepted. Governs FT-003 (event provenance), FT-008 (bootstrap session PROV-O), FT-011 (session lineage), and the slice 1 exit criteria in §11.2.
